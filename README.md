# 学习通作业助手

**一键扫描统计未完成作业，一键抓取整份作业生成 markdown 文件并复制，一键打开网页端 AI，
然后把复制好的文档直接发给 AI 生成答案。**

一键把**你所有课程**的作业扫出来，按课程分组看，一眼知道哪个还没做。  
不用再一门一门点开课程 → 我的 → 作业。

跑起来是个**本地桌面程序**（Edge 应用窗口，零额外 GUI 依赖），数据全部留在你自己电脑上。

> **本项目只读你自己的作业数据、只做汇总和提醒。不代做题、不自动交卷。**  
> 题目页能把题目整理清楚，方便你拿去问 AI 或自己写代码 —— 但代码里**没有**生成答案、填答题框、点提交这些路径，别往里加。

| 功能              | 说明                                                 |
| --------------- | -------------------------------------------------- |
| **一键扫全部作业**     | 一次把所有课程的作业拉下来，不用一门门点                               |
| **按课程分组看**      | 五态筛选（未交 / 待互评 / 待批阅 / 已完成 / 已过期），待办数标在课程名上         |

| **一键抓题目**       | 把待办作业的题干、输入输出格式、示例、代码模板全抓下来，落盘成 Markdown           |

## 安装（新机器 / 从零开始）

需要 **Python 3.10+**（本机实测 3.13）和 **Windows**（爬的是 Edge，界面也用 Edge 应用窗口）。

```bash
# 1. 装依赖
python -m pip install playwright

# 2. 装浏览器内核（本项目默认复用系统已装的 Edge，所以这步通常可以跳过；
#    如果提示找不到浏览器，再执行它）
python -m playwright install chromium

# 3. 启动界面
启动界面.bat
```

第一次启动会弹一个浏览器窗口让你登录学习通（扫码 / 账号密码都行，**密码不经过本程序**），  
登录完程序自动继续，之后不用再登。

**关于 Python 解释器**：几个 `.bat` 不写死 Python 路径，而是按这个顺序找 ——  
环境变量 `XXT_PYTHON` → 上次记住的路径（`.pyfound`）→ 几个常见安装位置 → PATH 上的 `py` / `python`。  
**每个候选都必须能 `import playwright` 才会被采用**，所以不会挑到一个没装依赖的 Python 然后在后面莫名其妙崩掉。  
找不到会明确告诉你去装什么。

想固定用某个环境，启动前设一下就行：

```bat
set XXT_PYTHON=C:\path\to\python.exe
```

**桌面图标**：跑一次 `python tools/install_shortcut.py` 生成。

**图标**：项目默认用的图标是从**学校校徽**裁的，校长徽和生成物都**没有**放进仓库  
（校徽不是个人的东西，公开仓库放它有版权 / 校规问题）。想要图标就自己放一张原图，  
然后 `python assets/make_icon.py`；或者直接生成一个中性占位图标：

```bash
python assets/make_icon.py --placeholder
```

## 怎么用

1. 双击桌面上的 **学习通作业助手** 图标（校徽那个）
2. 界面里点 **「开始扫描作业」**
3. 第一次会弹出一个浏览器窗口，在里面登录学习通（扫码 / 账号密码都行，**密码不经过本程序**）；  
   登录完成后程序自动继续，之后就不用再登了
4. 扫完自动出结果：摘要卡片 + 按课程分组的作业列表

界面里能做什么：五态筛选（未交 / 待互评 / 待批阅 / 已完成 / 已过期）、只看还需要动手的、  
按课程折叠、待办数标在课程名上、剩余时间按紧急度变色（≤24 小时标红）、点作业名直接跳学习通对应页面。

### 看题目：点一下把待办作业的题目全抓下来

界面上点 **「作业题目」** 按钮（右上角）进入**题目页**，里面只有**一个按钮**：  
**「一键抓取全部待办题目」**。

点它 = 把当前所有**未交 / 待互评且没过期**的作业，逐份打开作答页、解析成结构化题目，一次全抓下来。  
抓完每份作业摊开给你看：

- 题型、分值、标题
- **题干全文**
- **输入格式 / 输出格式**
- **示例输入 / 示例输出**（代码块原样保留，一行一个，可以直接拿来验你自己的代码）
- 作答要求、有几个选项、要不要交附件、指定语言

同时落盘成文件（见下面「代码结构」），离线也能看、能搜。

**为什么要有这个**：主看板只告诉你「有一份作业未交」，不告诉你「这作业到底要干什么」——  
以前你得点进去、等加载、一题一题翻。现在扫一次就全摊开了。

> ⚠️ **这个功能只抓题目、把题目整理清楚。不生成答案、不填写答题框、不提交。**  
> 见下面「风控与边界」—— 这是项目的底线，不是没做完。

**耗时**：一份作业 = 一个请求，走和扫描同一套限速（默认档约 1.9 秒/份），10 份待办约 20 秒。  
默认**不含已过期**的（抓了也没用，白花请求）；想连过期的一起抓，页面上勾一下。

### 不会做的题：页面顶部有「去问 AI」

题目页**最上面**有一行 **「不会做的题 —— 去问 AI：DeepSeek / 千问 / 智谱清言」**。点一下会：

1. **把当前列出的题目复制到剪贴板**（题干、选项、输入输出格式、示例、代码模板一起）
2. **用系统默认浏览器打开对应的 AI 网页**

到那边 `Ctrl+V` 就是完整的题目。只想复制某一道，用那道题后面的「复制本题 Markdown」。

⚠️ 说清楚它是什么：**它只是个快捷方式**。题目是你自己发出去的，那边的回答和本程序无关 ——  
尤其政治类选择题，那些 AI 给的答案同样不可靠，**拿去核对前请自己判断**。  
（本项目自己**不生成任何答案**，也不会把内容自动填进学习通。）

三个网址在 `src/server.py` 的 `AI_SITES` 里（2026-10-02 实测可达，注意 `tongyi.com` 已 302 到 `qianwen.com`）；  
打开接口带**域名白名单**（`_ALLOWED_AI_HOSTS`），非白名单地址一律拒绝 ——  
不设白名单它就变成一个任意 URL 打开器了。

**如果这三个按钮点了没反应**：页面会自动探测并显示一条橙色提示告诉你原因。  
界面窗口里的**网页**是每次打开时从磁盘读的（所以新按钮立刻看得见），  
但服务端**接口**是程序启动时载入内存的 —— 加了新接口就必须重启，见上面的 `重启界面.bat`。

### 空间被吃了：界面上的「清理缓存」按钮

界面窗口有自己的 Edge profile（`data\ui_profile`）。**Edge 会往每一个 profile 里塞它自己的组件**  
（`component_crx_cache`、`ProvenanceData`、`Edge Entity Extraction`……），实测涨到 **481 MB**，  
跟本程序的数据一点关系都没有。清理入口在**界面右上角「清理缓存」按钮**（题目页也有一个）：

1. 点开先**摊给你看**：会清哪些、各占多少、能释放多少，以及**哪些是保住的**；
2. 想连调试残留一起清，勾下面的复选框（默认不勾）；
3. 点「开始清理」→ 界面**自动关闭**（Edge 占着那个目录，不关删不掉）→ 清完**自动重开**。

> 窗口闪一下、进度提示没了 = 正常，别以为崩了。

**清什么 / 不清什么，只在一处定义**：`src/cleanup.py` 的 `_CLEAN_TARGETS`（白名单）  
和 `_PROTECTED`（保护清单）。这不是靠自觉，是**代码强制**的：

- **白名单**：只有列出来的路径能删。传白名单外的路径（哪怕是 `data`、程序根目录）→ 直接拒绝。
- **保护清单**：登录态、扫描结果、抓下来的题目、课程缓存、选课记录、代码、网页……  
  即使有人误加进白名单，也会被拦下并报错。
- **通配符保护**：`debug\homework_backup_*.json` 这类**带时间戳的数据备份**按前缀禁删 ——  
  所以白名单里能安全地逐个列 `debug\*.png` 截图，而不用怕顺手把备份清了。
- **指纹核对**：删除前后各拍一次保护清单的指纹（文件比对大小），对不上就大声报错。

|       | 安全档（默认）                                      | 完整档（勾选后）                                                                     |
| ----- | -------------------------------------------- | ---------------------------------------------------------------------------- |
| 清     | `data\ui_profile`、`debug\preview_profile`    | ＋ `debug\raw_html`、`debug\course_list_raw.json`、`debug\*.png`、`preview.html` |
| 实测释放  | 约 **495 MB**（清完 Edge 重建出 78 MB，净释放 ≈ 418 MB） | 再多约 2.3 MB                                                                   |
| 什么时候用 | 平时                                           | 排查完解析问题、或者想文件夹干净点                                                            |

**保住的（永远不动）**：`data\browser_profile`（登录态）、`data\login_state.json`（快照）、  
`data\homework.json`（扫描结果）、`data\tasks.json`（题目）、`data\题目\`、  
`data\courses_cache.json`、`data\selection.json`、`data\scan_log.txt`、`web\`、`src\`、`assets\`。

> 这个被**实测验证过**（2026-10-02）：清理前后 `data/browser_profile` 563 个文件 64,463,543 字节  
> 一字未变，五个数据文件的 md5 全部一致。回归测试见 `tests/test_cleanup.py`（15 条）。

**会自己慢慢涨回来的** —— 那是 Edge 的行为（它往每个 profile 下组件），不是本程序在写。  
涨到几百 MB 再点一下就行。

### 撞上风控：界面里点「过验证码」就行

被平台要求输图片验证码时，**主界面右上角和题目页顶部都有「过验证码」按钮**，点一下：

1. 程序先探一下现在是不是还被挡着（**只探这一次**）
2. 确认被挡，就把**验证码页面本身**打开在浏览器窗口里，并把它调到最前
3. 你在那个窗口里输 4 位验证码并提交 —— **不用回来点任何东西**，程序会自己发现
4. 发现验证码页跳走了 → 保存登录态 → 提示你「✅ 过了」

> ⚠️ 两个刻意的设计，都是为了别再往风控枪口上撞：
>
> - **不做网络轮询**。原来的命令行版是「提交后回来按回车，我再查一次」；界面版改成读  
>   **浏览器当前页面的 DOM**（`page.content()`）—— 零额外请求。风控期间每隔几秒发一个请求只会更糟。
> - **打开的是验证码页面本身**，不是学习通首页。首页本来就不受限、不弹验证码，  
>   照着做只会白忙一场（这是坑 5 的教训，界面上原来那段提示文字就是错的，已改）。

**这个按钮只在被风控要求验证码时才有用**，平时点了它会告诉你「没被挡，直接扫描就行」。

### 改完代码不用手动重启了

界面窗口里的**网页**是每次打开时从磁盘读的（改了 HTML 立刻可见），  
但服务端**代码**是进程启动时载入内存的 —— 所以以前改完 `.py`，光关掉窗口再双击图标是没用的，  
必须手动跑一次 `重启界面.bat`。

现在不用了：程序启动时会问旧进程「你加载的代码指纹是多少」（`/api/state` 里的 `fingerprint`），

| 情况                         | 行为                                             |
| -------------------------- | ---------------------------------------------- |
| 指纹**一样**（代码没变，你只是关了窗口又想打开） | 复用旧进程 + 把窗口调出来 —— 快，也不会打断正在跑的任务                |
| 指纹**不一样**（磁盘上的代码更新了）       | 让旧进程**自己退出**（`POST /api/shutdown`），然后用新代码重新起服务 |
| 指纹不一样，但旧进程**正在扫描/抓题**      | **这次先不重启**（免得抓一半的结果丢了），日志里写一句；等它跑完再双击一次图标就换成新版 |

所以现在的操作就是直觉：**关掉窗口 → 双击图标 = 用上新版本**。

> 指纹只算 `.py`（`code_fingerprint()` 里那 10 个文件）—— `web/*.html` 不算，因为它们每次从磁盘读。
>
> 从**老版本**升上来那一次会走兜底：旧进程还不认识 `/api/shutdown`，于是按端口找 PID 结束它  
> （先试 `taskkill`，被拒就改用 PowerShell 的 `Stop-Process`）。这一步如果也没成，  
> 会明确提示你双击 `重启界面.bat`。

命令行其他用法：

```
python src/main.py                      # 扫描 + 打开静态看板
python src/main.py --max-courses 30     # 这次只扫前 30 门（想快一点时用）
python src/main.py unblock              # 手动过一次图片验证码（同「手动过验证码.bat」）
python src/main.py --skip-retired       # 按 isretire 标记跳过课程（不建议，见坑 4）
```

**全扫要花多久**：70 门课大约 3～5 分钟。这个慢是我故意留的（见坑 5），别嫌它 —— 快是有代价的。

## 修过的七个坑（2026-09-23，别再犯）

### 1. 「全部获取失败」—— 是 CORS，不是网络问题

第一版把作业列表的请求放在**课程页里用 `fetch` 发**，想当然以为同域。  
实际上：课程中间页 `stucoursemiddle` 会 **302 跳到 `mooc2-ans.chaoxing.com`**，  
而作业列表接口在 `mooc1.chaoxing.com` —— **两个子域不同源**，  
于是 16 门课全部报 `TypeError: Failed to fetch` 而**课程列表却是好的**（很有迷惑性）。

**修法**：所有数据请求改走 `ctx.request.get()`（Playwright 的网络层），  
不受浏览器同源策略约束，也不会被 CORS 拦。原来那套 `page.evaluate(fetch)` 全部删掉。

### 2. 「扫描太慢」

每门课要真导航一次课程页（等页面加载完），16 门课要 1 分 33 秒。  
改成网络层请求后**不再需要渲染页面**，每门课只有 2 个 HTTP 请求，速度快一个数量级。  
真导航只保留为「万一拿不到 workEnc」时的兜底。

### 3. 顺带修：两个实例抢同一个浏览器目录 → 静默失败

两个程序同时用同一个用户数据目录时，第二个会**静默退出（exitCode 21）**，  
而且报错信息里看不出原因。现在加了单实例锁，重复启动会被明确拦住并提示。

### 4. 「本学期的课全没扫到」—— 我那条「跳过已结课」规则在误伤

第一版用课程列表里的 `isretire` 字段判断「是否已结课」（照抄了一份公开的逆向文档，没验证）。  
**实测这个字段根本不是那个意思**：他 70 门课里 `isretire=1` 的有 54 门，里面躺着——

- `26-27-1学期《形势与政策》`、`2026-2027-1《习近平新时代中国特色社会主义思想概论》`  
  （**白纸黑字写着本学年第一学期**）
- `Java EE企业级开发`、`HarmonyOS应用开发`、`软件工程`、`微信小程序`、`面向对象程序设计`、  
  `前端开发技术`、`数据库原理与应用`
- `概率论与数理统计`、`线性代数`、`高等数学下册`

而 `isretire=0` 的那些里，反而混着 `魅力科学`（结束时间 2026-01）、  
`人工智能与创新`（2025-07）这种早就结束的课。

**结论：这个字段不能用来判断是否已结课。**  
**修法**：默认**全扫，一门都不跳**。想看这个字段的原始取值就跑  
`python tests/inspect_courses.py`（会把 70 门课的 `isretire` / `endDate` 全列出来）。  
代价是请求量翻倍，所以坑 5 的降频是配套的。

### 5. 我自己把风控撞出来了 —— 请求太快

为了「更快」，我把请求间隔压到 0.2 秒、翻页 0.4 秒，然后一口气全扫 70 门课 ——  
**45 秒内打了 140 个请求**，平台直接返回：

> 【9010】操作异常，请输入图片中的验证码

更糟的是第二件事：**撞到验证码之后我没停**，把剩下 67 门挨个又撞了一遍，  
于是一次「输个验证码就能恢复」的小拦截，变成了整轮扫描全废。

**修法（三条，都是硬要求）：**

1. **间隔改成随机区间** —— 课程之间 1.5～3.5 秒、翻页 0.8～1.8 秒。  
   真人不会精准地每 0.2 秒点一次：**等间隔的机械节奏本身就是风控特征**。
2. **撞到验证码立刻熔断** —— `scanner.py` 抛 `VerificationRequired`，整轮扫描马上停，  
   并且**已经扫到的部分会保住**，不会白跑。
3. 界面和日志会明确告诉你中断在第几门、以及怎么恢复。

**恢复办法**：跑 `手动过验证码.bat` —— 它会把**验证码页面本身**直接打开在浏览器窗口里。  
（第一版这里只打开了学习通**首页**，而首页根本不受限、不弹验证码，老大照着做白忙一场。）  
你输入 4 位验证码并提交后，程序会**回访确认**是否真的解开，解开了才报成功；  
没解开会让你再输一次（最多 5 次）。  
**必须用程序自己开的那个浏览器窗口** —— 登录态在那个目录里，换浏览器解的不是同一个会话。

### 6. 「登录态莫名失效」—— 我把快照的恢复策略改错了

`data/login_state.json` 是登录态快照（浏览器目录里的 cookie 在程序被强杀时不会落盘，靠它兜底）。  
我一度把它改成「只在浏览器目录里完全没有 cookie 时才恢复」，想避免旧快照覆盖新状态。


结果实测：浏览器目录里只剩 **2 条** chaoxing cookie（残渣），而快照里有 **40 条**（完整）——  
那 2 条残渣被判定成「已有登录态」→ 快照不恢复 → 登录态「莫名其妙失效」。

**修法**：**总是用快照覆盖**。这是安全的，因为快照在所有会改变登录态的时机都会刷新  
（登录成功 / 过验证码 / 每次扫描结束），它总是「最新已知良好状态」。  
排查这类问题用 `python tests/check_session.py` —— 它会分别报「现状」和「强灌快照后」的结果，  
一眼看出是登录态丢了还是被风控挡了。

### 7. 「作业条数正好是 12」—— 第二页一直在被漏掉

作业列表页**没有分页栏**（`#page` 元素根本不存在），而我原来靠它读总页数 → 永远读成 1  
→ **所有作业超过 12 条的课都只取了第一页**。漏掉的往往正是最近布置的那一条，  
也就是最需要被提醒的那条。

更阴的是：**页码超出范围时接口会把第一页原样返回**，而不是返回空数组 ——  
所以「这一页有内容就继续翻」这种写法同样会掉坑。

**修法**（见 `scanner._has_more` 和 `scan_course` 里的去重）：

- 页面万一真给了分页栏，就听它的；
- 没给就按「**这一页满员（≥12 条）就再问下一页**」推断；
- 同时把每次返回的条目**按 workId 去重**，整页都跟前面重复就说明到头了。
- 代价只是可能白问一页（多一个请求），**绝不会漏数据**。

实测效果：`概率论与数理统计`、`龙芯现场工程师群` 都从 12 条补到了 **13 条**。  
回归测试见 `tests/test_paging.py`。

## 扫描速度：三个档位 + 选课器

扫描慢是因为**请求之间要故意留白**（等太短就会被要求输验证码，见坑 5）。  
两个手段解决：

**1. 选课器**：点界面右上角「选择课程」——  
弹窗里能搜课程、全选/全不选、**「只勾有待办的」**（推荐日常用），  
还能看到每门课上次的作业数/待办数。只扫十几门课就是几十秒的事。

**2. 速度档位**（在选课弹窗底部选）：

| 档位         | 每门课约   | 全扫 70 门约 | 说明                    |
| ---------- | ------ | -------- | --------------------- |
| 稳妥         | 3.4 秒  | 4 分钟     | 最不容易被风控。很久没扫、或刚被风控过时用 |
| **标准**（默认） | 1.9 秒  | 2.2 分钟   | 速度与安全的折中              |
| 快速         | 1.15 秒 | 1.3 分钟   | 明显更快，**被要求输验证码的风险更高** |

⚠️ 这些值别再往下调了。2026-09-23 我用约 0.25 秒/门（≈3.1 请求/秒）全扫 70 门，  
直接吃了一张验证码 —— 上面「快速」档已经比那次慢一倍以上。

**日常最省时间的做法**：点「选择课程」→「只勾有待办的」→「保存并开始扫描」。

**别再把 `src/config.py` 里那两个间隔调小。**

## 原理（万一以后失效了，照这个修）

学习通没有公开 API，走的是网页接口。三个关键请求：

| 步骤          | 接口                                                                                               | 说明                                                                                                                                                                                  |
| ----------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 课程列表     | `GET mooc1-api.chaoxing.com/mycourse/backclazzdata?view=json&rss=1`                              | 返回 JSON，`channelList[].content` 里含 `classId` / `cpi`，`content.course.data[0].id` 是 `courseId`                                                                                       |
| 2. 取 enc 令牌 | `GET mooc1.chaoxing.com/visit/stucoursemiddle?courseid=&clazzid=&cpi=&ismooc2=1&v=2`             | 从响应 HTML 里取 `<input id="workEnc">`；兜底用正则抠 `enc=[0-9a-f]{32}`                                                                                                                        |
| 3. 作业列表     | `GET mooc1.chaoxing.com/mooc-ans/mooc2/work/list?courseId=&classId=&cpi=&enc=&pageNum=`          | 返回 HTML，作业是 `<li data="详情页URL">`                                                                                                                                                    |
| 4. 题目（作答页）  | `GET mooc1.chaoxing.com/mooc-ans/mooc2/work/task?courseId=&classId=&cpi=&workId=&answerId=&enc=` | 返回「作业作答」页 HTML。题目在 `<div class="questionLi" typename="程序题" id="question<qid>">` 里；题干 = `h3.mark_name` 之后到 `div.clear` 之前。**URL 里的 `enc` 是第 3 步的作业列表直接给的，不用另外去取**（实测 314 条待办全都是这个形状） |

**几个容易踩的细节：**

- 状态文本**繁简混排**（「待互評」/「待互评」），必须正则模糊匹配。
- 作业**一旦过期，整个 `.time` 元素会被删掉**（不是改 class），此时状态仍写着「未交」——  
  所以不能一看到没有 `.time` 就判过期，要结合状态。
- 请求带上浏览器的真实 UA + Referer，别让请求看起来像裸脚本。

## ⚠️ 风控与边界

**这是走网页接口，不是官方 API。** 已知风险：

- 短时间内大量请求可能触发验证码，极端情况账号临时受限。
- 平台改版可能导致解析失效（改版后看 `data/scan_log.txt` 和 `debug/raw_html/` 的原始响应来修）。

已经做的防护：**串行扫（不开并发）**、每门课只有 2 个请求、  
**课程之间随机等 1.5～3.5 秒、翻页随机等 0.8～1.8 秒**、  
**撞到验证码立刻整轮熔断**、失败重试 2 次、抹掉 `navigator.webdriver`、  
最多扫 150 门（够覆盖全部课程）。

想更保守：`python src/main.py --max-courses 30`，或设环境变量 `XXT_MAX_COURSES=30`。  
**别调小 `src/config.py` 里的等待间隔**，那是拿账号安全换速度。

**功能边界：只读你自己的作业数据、只做汇总和提醒。不代做题、不自动交卷。**

题目页（`web/题目.html` + `src/tasks.py`）也一样：**只抓题目、只整理题目**。  
不生成答案、不填答题框、不点提交 —— 代码里没有这些路径，别往里加。

| 现象                       | 原因 / 处理                                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **被提示「被风控中断」/ 要输图片验证码**  | **点界面上的「过验证码」按钮**（主界面右上角 / 题目页顶部）—— 程序会把验证码页面直接打开在浏览器窗口里，你输完它自己会发现，然后回去重新扫描（见坑 5）。命令行等价：`手动过验证码.bat`                                        |
| 扫得比以前慢                   | 正常的。以前是拿风控风险换速度（见坑 5），现在故意放慢了                                                                                                               |
| 提示「登录态无效」                | 在界面里重新点扫描并按提示登录；或跑 `登录学习通.bat`                                                                                                              |
| 提示「已经有一个在运行」             | 上一次的窗口还没关，关掉再开                                                                                                                              |
| 某门课显示「没拿到 enc 令牌」        | 该课可能没作业、或页面结构变了。看 `debug/raw_html/middle_<课程id>.html`                                                                                       |
| 课程数量看着不对                 | 跑 `python tests/inspect_courses.py` 看接口返回的全部课程与原始字段                                                                                         |
| 扫出来是空的                   | 先看 `debug/raw_html/worklist_*.html` 里的原始 HTML，对照上面「原理」改 `src/parser.py`                                                                     |
| 界面打不开                    | 跑 `启动界面.bat`（会保留一个控制台窗口，能看到报错）；再看 `data/app.log`                                                                                            |
| 想看细节                     | `data/scan_log.txt` 是扫描日志，`data/app.log` 是界面进程日志                                                                                            |
| 题目页说「没有需要抓的作业」           | 待办是空的，或者你还没在主界面扫过作业。先回主界面扫一次                                                                                                                |
| 题目页点了按钮弹出浏览器窗口           | **正常**，别关它。抓取要用登录态，抓完自己会关                                                                                                                   |
| 某份作业「没解析出题目」             | 看 `debug/raw_html/task_<workId>.html` 的原始响应，对照「原理」第 4 行改 `src/task_parser.py`；页面上会把页面正文原样留档，不会白抓                                            |
| 抓题目时被风控中断                | 同「扫描」：点界面上的「过验证码」，过完再回来重新点抓取。**已抓到的部分会保住**                                                                                                  |
| 点「作业题目」显示「这个地址没有页面」(404) | **界面还是更新前的旧程序**。窗口里的网页是每次打开时从磁盘读的（所以新按钮能看到），但服务端路由是程序启动时载入内存的（所以新页面打不开）。**关掉窗口重新双击桌面图标即可，不用重新登录**（新版本会自动接管）。点了按钮会先探测一下，不通会直接弹窗告诉你，不会把你丢进死胡同 |
| 改了代码，怎么生效？               | **关掉窗口、双击桌面图标就行** —— 程序会比对代码指纹，发现磁盘上的代码更新了就自动用新代码重启服务。只有旧进程正在跑任务时才会跳过（免得结果丢）                                                                |

## 🔒 隐私：什么留在你电脑上，什么会上传

**一句话：全部留在你电脑上，什么都不上传。**
本程序没有服务器、没有后端、没有任何遥测。唯一的网络请求是发给你自己的学习通账号。

也正是因为这样，下面这些东西**被 `.gitignore` 排除，永远不会进仓库**：

| 路径 | 里面是什么 |

| `data/courses_cache.json` / `data/selection.json` / `data/scan_log.txt` | 课程缓存、你的勾选、扫描日志 |
| `data/ui_profile/` | 界面窗口的浏览器缓存（几百 MB） |
| `debug/` | 排查用的原始响应 HTML，里面含作答页 URL、workId |
| `assets/校徽原图.jpg` 及生成的图标 | 学校校徽（版权 + 等于公开「哪个学校」） |
| `.pyfound` | 本机 Python 的绝对路径 |
